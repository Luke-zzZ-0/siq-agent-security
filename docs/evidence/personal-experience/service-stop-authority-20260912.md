# M81：当前运行绑定的退出授权核心

日期：2026-09-12。规格 §3.11.43；新增 `internal/localcontrol`、`local-service-control-challenge/v1` 与 `local-service-stop-request/v1` 合同，候选为基于 274ed97 的后继本地增量。

每次控制器构建生成随机 boot_id，挑战绑定目录与 30 秒时限，使用现有本机 Ed25519 密钥签名。CLI 核对挑战来源、目录、时限后签署不同 schema/action 的 stop 请求。控制器锁内核对当前运行/目录/有效期/签名，只在必要接受记录回调成功后消费一次；失败不授权退出，并发重复和重放拒绝。

## 验证

- Go 全量、vet、localcontrol race（1.040 秒）、CLI race（6.364 秒）通过。
- 正向签署/接受；过期、过远未来、其他 boot、其他目录、篡改签名、挑战直接重放、错误密钥与所选目录、重启重放拒绝。缺少接受回调和记录失败拒绝，记录失败后可重试；16 个并发请求只接受一次、执行一次成功记录。
- 两个固定 Go JSON 样例由 seed=7 测试密钥签名（非生产凭据），Python 验证 schema、规范签名、字段关联、域分离与非法字段/数值。共 163 项合同测试与 Ruff 通过。
- linux/arm64、linux/amd64、darwin/arm64、windows/amd64 的 `go build ./...` 通过，包含新包。新包尚未接入主程序，不将编译计为退出功能已经可用或原生后台已验收。

## 后续接入要求

本批不新增 HTTP 路由或 CLI，不发退出信号、不释放 Writer，不替代服务端接受记录。后续必须在受限本机端点严格解析消息、拒绝其他凭据替代签名，提供必要持久化接受记录回调，再通知现有 drainingHandler 排空；回执只能表示接受，不能提前表示服务已退出。需以运行标识、正常退出结果和 Writer 释放完成最终确认。

同 UID 能读取私钥的进程仍可授权停止，该核心不提供同用户进程隔离。Windows 退出、注销及原生旅程待完成，UX-003 保持 doing。未提交、推送、发布或合并本批功能。
