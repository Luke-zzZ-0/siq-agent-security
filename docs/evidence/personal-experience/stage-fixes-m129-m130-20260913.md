## 修复

1. **限制场景真实执行语义**：共享的 ScenarioAllowsEffects 按标准化效果限制操作。授权生成过滤工具声明与平台列表；草稿编辑拒绝重新加入被场景禁止的权限；RuntimeToolSets 对旧 Grant 的列表和事实同样收紧；Runtime Identity 会话包络收紧工具及效果；逐调用裁决再次检查。no-exec 拒绝进程执行/未知操作；no-network 拒绝出网、消息发送和不能保证不出网的通用执行入口；sandboxed 仅留已识别的只读效果，显示名称改为“只读权限”，不宣称 OS 沙箱。只读仍需已有路径权限，fs.read 的 DesiredPolicy 投影保持只读。普通无场景与 advisory 合同保留。
2. **场景切换不能静默复用**：同 ID 的 live Grant 仅在场景 ID/版本一致时复用，不同场景含基线互换返回 409 grant_scenario_conflict。原 Grant、签名、状态修订保持不变；不自动撤销或替换已生效权限。
3. **通知失败独立退避**：失败设置 retryAfter，15 秒内不重复尝试；待办归零不清除尚未到期的失败退避；成功后清除退避并保留正常合并逻辑，失败不吞待办。
4. **日志不接收通知子进程输出**：使用直接 argv 与 cmd.Run，stdout/stderr 保持 nil、直接进入空设备，没有 CombinedOutput 缓冲；错误仅返回固定失败/超时类别，启动失败也不回显命令路径；最长 5 秒。

补充修正：场景目录返回独立切片，避免调用方修改目录规则；两个通知不可用测试使用隔离 PATH 代替基于宿主环境的 SKIP。它们现在确定性通过，不把缺少桌面实测伪装成平台支持。

规格：`docs/agentshield-dev-spec-v1.md` §3.12.34。新增运行检查复用既有 reason_code `grant_scope_violation`，不新增或放宽 Authority。管理接口保留原形状，不覆盖历史签名 Grant。
