### 2.1 不能为了进度修改的边界

1. `effective` 只来自执行后端读回；declared/inferred/observed 分开。安装成功、签名存在、扫描无威胁均不等于已隔离或已生效。
2. 必需 Authority 无效始终 hard deny；block 模式决策服务不可达拒绝。普通 advisory 行为按现有规格，不擅自扩大或收紧语义。
3. Skill 自报身份、路径/cwd 匹配、模型输出不能授权。未知归属保持 unknown，待可信宿主链验证后才提升。
4. 私钥不出状态目录；管理 token 不进 URL、通知、Web Storage、日志。敏感源定位信息不能随更新调度泄漏。
5. 静态扫描不运行 Skill；获取不执行仓库钩子/依赖脚本/filter/LFS/submodule。测试传输缝不得由运行时配置启用。
6. 撤销、过期、换主体/版本/参数后旧批准不可复用；不重签历史、不用回退备份复活授权。
7. 仍是 desktop-same-uid 信任边界，不宣称能防同 UID 恶意进程直接操作任意文件。
8. 企业身份派生 tenant_id；审计/outbox 与状态同事务；凭据服务端只存哈希；生产不使用 SQLite、自动建表或 X-Dev-*。
9. `apps/agentshield` 保持 stdlib。新增桌面框架/独立服务/沙箱/外部依赖先有 ADR，不复制现有决策、审批、下载、任务或资产引擎。
10. 不修改冻结比赛/研究发布快照，不以测试签名冒充正式发行。本次提交/合并授权不等于发布安装包、使用付费模型或修改仓库治理。

## 5. 个人阶段详细要求

### N02：恢复有真实安全边界的仓库来源获取

**范围：** UX-009/010；主要位置 `internal/skillimport/{git,upstream}.go`、下载实现、`internal/skillinstall`、服务端和前端来源入口。

**实施：**

1. 先形成 ADR：是支持有限公共托管商的 HTTPS API → 固定 commit 归档，还是实现通用 Git HTTPS 传输。前者应明确供应商/URL 支持范围；不能把归档下载伪装成任意 Git clone。私有源认证单独设计安全引用，缺失能力明确不可用。
2. 出站策略必须作用于实际连接：校验并绑定 DNS/IP，拒绝私网/loopback/link-local/IPv4-mapped 等被禁地址及混合解析；重定向重新校验，防 DNS 重绑定。只检查原 URL 不够。
3. 通用 Git 方案还须覆盖协议内部的跳转、alternate/object URL 和子进程网络连接。清除危险代理/配置/凭据 helper 环境；禁用其他协议、钩子、submodule、LFS/filter 和任意代码执行。不能用可注入的用户 `.gitconfig` 或浏览器 Cookie。
4. 解析引用后固定不可变 commit；SubDir 和工件摘要绑定。获取、解包/checkout、文件数、单文件/总大小、磁盘和时间均有上限；取消/超时/失败清理临时目录。
5. 补完整 Git create/result/list、来源元数据与更新比较合同，核对现有 v2 消费端兼容。来源 URL 中的凭据和查询敏感值不进入持久化审计、日志、API 错误或追溯包。
6. 只有生产真实调用路径通过验收后才启用 Git；继续复用同一静态检查、权限预览、确认和安装事务。

**必须测试：** 正常公共仓库固定 commit/SubDir、分支前进被检查识别；跨 host 重定向、解析混合地址、重绑定、协议走私、恶意 Git 配置、超大对象/归档、路径逃逸、超时、取消、远端删除；测试缝和生产传输分开登记。真实托管服务至少一个成功和一个受控失败，报告不含私有仓库身份或凭据。

**完成门槛：** 审阅者能从 URL 到最终连接/内容验证完整边界；只有本地 `file://` fixture 不算完成。没有安全方案时保留拒绝并记录具体阻塞，不降级为不受限 clone。

**范围：** UX-010；复用 `update_check.go`、`update_compare.go`、现有更新事务、`SkillUpdateCheckPanel` 和已安装 Skill 页面。

**实施：**

1. 当前 ZIP 记录以来源定位摘要绑定，调用方再次提供 URL；浏览器仅在内存保存 URL。自动检查不能偷偷将完整地址塞进 Web Storage 或审计。先设计可自动重取的来源配置：安全公共定位信息与私有/临时认证引用分离，保存范围和用户控制明确；不满足条件的安装显示“需要重新提供来源”。
2. daemon 提供有界调度：建议默认每 24 小时、随机抖动、有限并发、失败退避；这些是实现默认值，写入规格并测试，可由用户关闭。手动检查优先但不产生并发重复任务，重启后避免集中请求。
3. 检查只更新独立检查状态/调度元数据，不修改安装版本、Grant、准入工件或更新操作。保持现有 `CheckUpdate` 对安装状态的只读保证；测试明确允许哪些调度文件写入。
4. 状态包括未检查、检查中、已最新、有新版、来源不可用、暂不支持；显示最后成功时间，失败不能显示“已最新”。截断差异显示实际数量/截断提示；`deferred_to_update_comparison` 不能显示成权限无变化。
5. “有新版”只启动已有比较/确认流程；再次取得候选后绑定不可变内容和权限差异。来源再次前进、候选过期、安装/移除并发、Grant 修订变更时旧检查结果不能授权更新。
6. 真实宿主更新后验证发现、平台识别、允许操作、越权拒绝、旧会话/旧授权失效及恢复。更新与移除保持显式确认。

**必须测试：** 受控时钟的调度/重启/退避、关闭后不发新请求、离线后恢复、取消与迟到响应、私有/过期来源、来源替换拒绝、210 项差异截断、零安装状态写入、用户确认前版本不变、TOCTOU 旧候选拒绝。通过真实 HTTPS ZIP/受支持 Git 与一个原生平台的更新旅程，再补全部要求的组合。

**验收：** 每个平台至少一条“发现 → 预览 → 接入 → 正常允许 → 越权阻断 → 服务离线阻断 → 配置还原”原生旅程；缺某 OS 的对应行保持 blocked。采集实际命令/版本/脱敏证据和清理结果，不安装到用户正在工作的默认实例。

### N05：可信 Skill 执行归属与真实权限交集

**范围：** UX-007/011；主要位置 `runtimeidentity`、`grant`、`receipt`、Skill 安装记录和平台桥。

1. 从 N04 选择可证明的宿主调用元数据或受控启动链。运行归属应绑定平台实例、agent、session/task、Skill 的安装记录与不可变内容摘要、调用 ID 和有效期，信任根来自本机受信宿主链。
2. `SKILL.md` 文本、自报 skill_id、工具参数、cwd、文件名或内容匹配只能提供线索，不是可信执行证明。没有证据继续 unknown，不凭“宿主通常这样做”启用强制归属。

**必须测试：** 伪造/缺失/篡改 claim、相同内容不同安装、同名 Skill、跨实例、A Skill 复用 B 授权、旧版本和旧会话、混合调用、撤销并发、场景不一致 409、不支持效果拒绝。至少真实宿主越权请求被拦截且没有实际副作用。

**完成门槛：** 必须有运行时可信来源证据和真实执行层拒绝；仅元数据核验和 API 签名测试不能关闭 UX-007。

### N06：统一确认后的真实继续执行与通知

**范围：** UX-008；复用 pending/inbox、现有签名批准机制、平台钩子和 `internal/notify`。

1. 先复现 Hermes 回调等待上限与 OpenClaw/WorkBuddy 的恢复语义。选择平台支持的暂停恢复或受控重试；不能仅延长 HTTP timeout、阻塞无限等待或让模型“记住已批准”。
2. 同一请求生成有期限、可审阅、可撤销的待办。批准绑定主体、具体操作/资源、关键参数摘要、Skill 版本、Grant/组织策略修订；在最后可用执行检查点重新验证。
3. 一次批准只消费一次；客户端重试、daemon 重启、响应丢失和重复通知不得重复执行。平台不能透明恢复时，明确显示“已批准，请返回原平台重试”，并保证重试安全；该替代是否满足完整体验须单列验收。
4. 默认“拒绝/允许本次”；任务内同类授权单独定义次数、资源范围、任务寿命和撤销。硬禁止和无效必需 Authority 不进入可批准绕过路径。
5. 补齐 Windows/macOS 的默认通知方式与真实投递。通知内容只含必要计数/概要，点击进入正确 SIQ 待办；通知不能携带管理 token、原始命令或直接批准。
6. 通知权限被拒、无图形会话、命令失败时降级至 inbox，保持独立退避；不记录通知子进程原始输出。系统通知是否自动导航须实机证明。

**验收：** 用户未回应不执行；允许一次只产生一次真实结果；拒绝/过期/改参/换 Skill/撤销后均不执行；重启/重复回调/网络断开不会重复副作用。每系统至少实际通知与恢复证据，headless 测试不能代替桌面投递。

## 6. 团队阶段详细任务（N09 通过后执行）

### T01 / LAN-001：复用控制面的局域网部署

- 核对现有 Control API、Worker、PostgreSQL、企业 UI 与迁移，不新建独立团队后端。输出实际拓扑、DNS/TLS、OIDC、首次管理员、配置/Secret 引用、健康、备份与恢复说明。
- 开发 Compose 的 loopback/开发身份不能原样作为团队生产部署。生产走 TLS 和已验证身份，干净 PostgreSQL 执行 Alembic；不能自动建表或依赖兄弟项目数据库。
- 设备主动出站连接控制面；个人管理 API 默认仍仅 loopback，不为方便团队访问直接暴露本机管理员端口。
- 验证远端局域网设备的真实访问、身份拒绝、证书错误、迁移与备份恢复；全部关键写操作断言审计/outbox 同事务。

**完成门槛：** 一台团队控制面与至少另一台真实设备经受控入口通信；单机容器互通只是组件证据。

### T02 / LAN-002：加入团队、设备身份和退出

- 复用 `environments.py` 的 enrollment/register/heartbeat 和 Edge 身份。个人 UI 解释团队归属、上报范围和策略影响，经明确确认后加入。
- 单次、限时接入码并发消费安全；身份来自注册结果和验证凭据，服务端仅存设备凭据哈希。设备端用系统安全存储/受保护引用，不能前端持久化明文。
- 完成拒绝加入、心跳、离线、吊销、退出、重新加入、凭据轮换、设备重命名和重装。团队身份不能覆盖本机个人状态实例 ID。
- 在线每次请求校验吊销；离线设备无法即时收到撤销，应明确最后可信状态、过期和重连行为，不宣称离线立即生效。
- 退出前显示组织要求与可保留个人数据；本机个人模式恢复不能复活已撤销的组织授权。

**负向验收：** 重放/过期码、并发注册码、旧凭据、跨团队身份、冒名设备、重装冲突、断网中途加入与退出；两台真实设备材料分开。

### T03 / LAN-003：多设备资产、归属与隐私

- 资产键至少由 tenant、device、platform instance、agent/Skill 安装身份构成；同名和相同内容跨设备不能错误去重。
- 复用 inventory 上报与事件合同，增加必要版本字段；区分当前快照、删除/失联、最后观察时间和来源。用户选择上报范围，默认不上报原文、秘密、完整私有路径/URL。
- 企业 UI 展示设备 → 实例 → 智能体 → Skill 关系、真实保护能力和状态；不能把 last_seen 当在线、安装当受控。
- 设计数据保留、脱敏和租户/角色可见性；增量/重放幂等，重连不复活已移除资产。

**验收：** 两设备同名资产互不覆盖；跨租户定位与授权按仓库规则拒绝；断网/删除/重装/乱序事件状态一致，默认上报包无原文或凭据。

### T04 / LAN-004：定向与批量任务

- 当前环境级竞争领取不能充当广播。扩展明确 `target_device_id`，批量请求展开独立子任务，并绑定固定目标快照、父批次和各设备结果。
- 复用现有 lease/claim/ack/outbox；领取原子性、幂等键、重试、租约到期、取消、部分成功有协议定义。一个设备不能领取另一个设备的任务。
- 不把网络投递 exactly-once 等同真实副作用恰好一次；不可幂等动作需要执行日志和去重/人工恢复策略。任务回复只有有效设备身份与目标绑定才能改变状态。
- 企业 UI 可见排队/已领取/运行/成功/失败/超时/取消及每设备明细；部分完成不能显示全批成功。

**验收：** 两设备目标产生两份独立结果；同时抢租约、掉线重领、重复回执、跨设备/租户请求、过期签名、部分失败和取消竞态被正确处理。

### T05 / LAN-005：组织策略的实际应用与回报

- 策略含发布者身份、tenant/device 或组范围、版本/摘要、生效/到期、签名及撤销语义；本机验证后经现有权限引擎应用，不能绕过本地安全检查。
- 个人授权不能放宽组织上限；定义冲突的保守交集和解释 UI。组织不可接受的操作不能弹出个人“允许”绕过。
- 明确 `published / received / applied / verified`：收到字节不等于生效，生效须后端配置读回，verified 还需要真实允许/拒绝验证。
- 断网使用有期限的最后可信策略；过期和需在线批准的行为按定义拒绝。恢复联网验证撤销/版本单调性，不能接受旧策略重放。
- 应用失败可恢复；权限状态、审计和回执关联同一修订。没有后端执行能力的限制标不可用，不能仅在企业页面显示绿色。

**验收：** 篡改、旧版本、错租户/目标、未知签名、过期、离线、冲突、只收到未应用、应用中崩溃；两台真实设备各自证明实际行为改变且越权未产生副作用。

### T06 / LAN-006：两台真实设备闭环及扩展

- 使用至少两台真实局域网设备，优先不同 OS，逐台完成加入 → 资产 → 定向/批量任务 → 策略 → 允许/拒绝 → 离线 → 重连 → 吊销/退出。
- 核验本机与企业回执、时间、设备身份、任务和策略版本关联；默认隐私边界不随加入团队消失。
- 增加多设备模拟负载、数据库竞争、重试风暴、时钟偏差、网络抖动、积压清理测试，记录实测容量和瓶颈。模拟规模不能替代两实机验收，也不能凭单次测试承诺企业容量。
- 交付部署/升级/备份/故障排查/退出手册，记录已知限制和支持矩阵；独立审阅租户隔离和权限生效证据后关闭团队阶段。

## 7. 给 GLM 的具体实现指导与验收用例

### 7.1 优先解决 N02，避免再次“放开 clone 就算完成”

现有入口为 `apps/agentshield/internal/skillimport/git.go` 的 `fetchGitCLI`；它在查找程序、启动子进程和联网前返回 `ErrGitTransportUnavailable`。`cloneGit` 及本地 fixture 是历史组件能力，不能直接替换生产拒绝。读取 `remote.go`、`upstream.go`、`tree.go`、`zip.go`，复用已有 URL、预算和工件检查，但逐项证明实际网络连接也受约束。

实现方向可在不降低需求的前提下自行选定：**先支持明确列出的公共托管来源，用受控 HTTPS 元数据解析得到不可变 commit，再按该 commit 取得受限源码归档**。这只是建议方案，先写 ADR/规格并验证托管端的实际 API/重定向语义；不能硬编码猜测的 URL。不得把可变化的 branch 下载结果标为固定 commit。若坚持通用 Git，必须覆盖其所有子进程、协议内部对象请求和配置影响，安全证明成本明显不同。公共受限方案的第一批不自动承诺任意 Git 托管、私有凭据或所有引用形式。

具体执行：

1. 列出接受的 host/port/path/ref/commit/SubDir 语法，以及不支持输入的稳定错误。用户 URL 不能变成请求任意内网资源的模板；每个供应方 API 请求及归档跳转也执行地址检查。
2. 用可控 DNS/HTTP 组件测试验证实际拨号绑定；TLS 仍验证正确主机，不因绑定 IP 关闭证书验证。禁用环境代理或明确受控策略，拒绝混合公私解析和协议跳转。DNS 超时、连接超时、读取超时与总超时都有上限。
3. 获取前解析目标引用，记录真实不可变 commit；下载内容必须绑定该 commit，防引用在两次请求之间变化。归档顶层目录和 SubDir 不能逃逸；内容清单/预算检查与现有准入流程共用。
4. 增加/升级必要合同，不改旧签名字段语义。核对 `local-skill-import-git-create.v1.schema.json` 及现有记录、result/list 的所有生产方与消费方。固定 commit 不等于取得执行许可。
5. 在测试公开仓库验证真实 create → list → compare/confirm → install，以及上游前进 → update-check 的生产路径。网络失败不能落成成功记录，不能泄露源地址敏感部分；实测不可用时保留默认拒绝。
6. 只有受支持路径全部通过后在能力报告/UI 显示可用；其他 host/协议继续拒绝，并提示用户使用已支持 HTTPS ZIP 或本地导入。

| 用例 | 期望 | 需要断言的副作用 |
| --- | --- | --- |
| 固定 commit 与合法 SubDir | 内容、commit、安装目标一致 | 未确认前目标目录/Grant/当前安装版本不变 |
| 分支在解析后前进 | 使用已解析候选或明确拒绝漂移 | 不把后到内容冒充原 SHA |
| 跳转到内网/混合解析/IPv4-mapped | 拒绝实际连接 | 拒绝发生在拨号前；测试服务器没有收到被禁请求 |
| 恶意配置/helper/协议/钩子 | 不执行、不读取用户凭据 | 没有哨兵文件/外部进程副作用 |
| 过量文件/字节、路径逃逸、特殊文件 | 有界拒绝 | 无目标安装写入、临时目录按归属清理 |
| 取消/超时/远端删除 | 分类错误，可重试/明确不可用 | 不留成功工件、不泄露响应原文 |

### 7.2 N03 把“自动”限定在检查，保持确认安装

先核对现有 `internal/skillinstall/update_check.go`、`update_compare.go`、`internal/server/skill_install.go`、`local-skill-update-check*.schema.json` 和 Web `SkillUpdateCheckPanel`。已有 CheckUpdate 纯只读安装状态的契约必须保留。

新增调度元数据与安装记录分开，使用 N01 的兼容读写与锁。记录来源引用、开启/关闭、下次检查、最后尝试/成功、稳定结果和失败类别；结果不保存敏感 URL。对新增存储定义 reader/writer 的兼容策略，不能让旧程序把新数据误当成旧结构。字段和 API 名称先设计后实现，此处不要求另造固定命名服务。

并发控制至少绑定“本地安装操作 + 当前内容/修订”；手动/自动同时检查合并或串行。关闭、移除、重新安装后迟到结果不更新新对象。重启后按有限队列恢复而非一次性请求全部来源。调度器只记录结果，绝不自动调用确认、Grant 扩权或切换安装。

UI 显示最后成功时间、当前来源能力、差异截断和权限比较未完成状态。点击更新必须重新走已有候选比较与确认事务，批准绑定再次验证后的候选。为“检查新版本”和“确认安装新版本”分别写用户级测试。

### 7.3 N04/N05/N06 必须解决真实调用链

优先复用 `adapters/runtime/hermes-agentshield/`、`adapters/runtime/openclaw-agentshield/`、`internal/adapterinstall/`、`runtimeidentity/`、`pending/`、`notify/`；`connectors/workbuddy/` 是发现能力起点，不证明 WorkBuddy 有运行时前置钩子。查最新官方资料时记录直接来源、日期及所测版本；厂商当前能力未知不能靠模型记忆补齐。

每种平台先写一条完整时序：用户原平台发起调用 → 宿主提供可信上下文 → SIQ 决策 → 如需批准则等待/受控重试 → 最终执行前复验 → 执行 → 原生结果关联 → SIQ 活动。时序中标出信任根、不可伪造字段、调用/会话唯一性、超时与取消。无法证明的节点保持 unknown/unverified。

必须区分三件事：

- 能读取 Skill 清单：资产发现。
- 能在某工具调用前拒绝：该调用路径保护。
- 能证明这次工具调用由特定已安装 Skill 触发：可信 Skill 归属。

前两项不能自动推导第三项。不能要求模型在工具参数里填 skill_id 并以此授予权限。受控启动只有在完整执行链可验证时才提高该组合的能力等级。

一次批准的数据绑定和实际一次执行分开验证：pending 的单次消费正确仍可能因宿主重试产生重复副作用。使用隔离测试资源/哨兵观测真实执行次数；发生响应丢失时，若无法保证安全重试，应显示结果未知并要求核验，不能自动重放写入。

### 7.4 N07/N08 交付用户真正能走通的入口

先复用 `start-local.py`、现有 Go 命令、Go embed 与系统生命周期模块。普通用户最终不必自己启动 Control API/Python/npm 才能使用个人版；前端“未连接”应解释个人本地服务的状态并给出正确恢复动作。开发模式 `/`、`/demo` 回落和生产 embed 深链分别验证。

安装包把已有初始化、用户服务注册、打开浏览器和管理恢复串联；不要把发布测试二进制、生成服务文件或启动命令成功当作安装体验验收。由用户显式选择接入实例、权限、开机自启和卸载数据保留项；失败时明确已经做了什么、当前是否受保护、下一步如何恢复。

N01 迁移是显式操作。升级流程需要迁移时先解释支持窗口、备份和停止要求，再执行确认；遇到实例/备份漂移保留现场。系统签名凭据、macOS notarization、Windows 信任提示和真实 OS 验收分别记录，不用测试密钥代替。

首页与详情共用真实 API 状态；系统通知只导航到 SIQ 待办，通知被拒不影响 inbox 可处理。原文仓状态、撤销与保留期的错误不能被“任务成功”遮盖。
